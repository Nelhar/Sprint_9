# ADR-003. Стратегия размещения данных

| Поле | Значение |
|---|---|
| Статус | Принято с условием: пересмотр после заключения юристов (до 19.09, Q-06) |
| Дата | 2026-08-28 (время кейса) |
| Владелец решения (A) | CTO Р. Менон; политическое условие «данные в стране» — инвестор К. Орлов |
| Консультировались (C) | Внешний юрист А. Нвосу, будущий DPO, CFO (стоимость ячейки) |
| Информированы (I) | CEO, Head of Marketing (согласия) |
| Противоречия | C-05 (данные в стране ↔ любой гиперскейлер), C-06 (ждать юристов ↔ 15.10), C-07 (купленная база ↔ POPIA) |

## Контекст и проблема

ПДн нигерийцев «должны храниться на территории» (A3 п.1), а инвестору нельзя получить «звонок министра» (A1, A7). Ни у одного гиперскейлера нет региона в Нигерии. Юристы дадут конкретику через 4–6 недель и советуют до этого архитектуру не фиксировать (A3), а запуск — 15.10 (A1, A7). Нужна схема, которая **запускается с консервативным допущением и переживает ответ юристов без переписывания**.

## Факторы решения

Худшее правдоподобное прочтение NDPA · запуск к 15.10 · ≤ $5k/мес (A6 п.1) · 6 человек — одна платформа, а не две · обратимость · задержка для Лагоса.

## Рассмотренные варианты

| Критерий | 1. Всё в af-south-1, ПДн NG зашифрованы | 2. Вся платформа дублируется в Нигерии | **3. Ячейки по странам: ядро в af-south-1, ячейка NG в Лагосе** |
|---|---|---|---|
| «Данные в стране» | ✗ шифрование ≠ локализация | ✓ | ✓ |
| Срок 15.10 | ✓ | ✗ две платформы | ✓ |
| Стоимость | Минимальная | +$2–3k/мес | **+$990/мес** (TCO A, стр. 13) |
| Эксплуатация (6 чел.) и обратимость | Проще; переезд позже = переписывание | ✗ / ± | ✓ общие EKS, IAM, CI/CD; ✓ |

Вариант 4 — «ждать юристов» — срывает 15.10 и рассмотрен в обосновании.

## Решение

**Ячейки данных по странам** с консервативным допущением для Нигерии.

1. **Ядро в AWS af-south-1:** каталог (не ПДн), оркестрация, данные Кении (по SCC ODPC) и ЮАР (в стране).
2. **Ячейка Нигерии в AWS Local Zone Лагос:** своя точка входа (ALB, домен `api-ng`, TLS в Лагосе), роли монолита `cell-ng` и `worker-ng`, PII-хранилище. Хранит профили, адреса, **заказы и платежи нигерийцев (включая псевдонимизированные)**, KYC продавцов NG, согласия. PostgreSQL — self-managed (CloudNativePG ×2): RDS в Лагосе нет (исключение CN.MSV.01).
3. **Вторая площадка в Нигерии — MTN Cloud:** WAL и бэкапы. Выгрузка снапшотов EBS в родительский регион запрещена политикой.
4. **Маршрутизация по стране — на клиенте:** приложение ходит прямо в `api-ng`, партнёров NG вызывает воркер ячейки через NAT-инстансы в Лагосе. Ядро запросов с ПДн нигерийцев не получает ([data-residency-map.md](data-residency-map.md) §4).

| Аспект | Решение |
|---|---|
| **Маскирование** | Токенизация в PII-хранилище страны; в UI поддержки — последние 4 цифры; логи маскируются на источнике; аналитика — агрегаты с k ≥ 10. На допустимость маскирования по A3 п.1 **не опираемся** до заключения юристов |
| **Шифрование и ключи** | TLS 1.2+; диски — AES-256 (KMS). Полевое шифрование ПДн ключами страны: NG — OpenBao в Лагосе, KE/ZA — KMS af-south-1. Ключ данных на покупателя — для crypto-shredding. Ротация раз в год |
| **Репликация** | NG: синхронная реплика в Local Zone + WAL на MTN Cloud (Barman Cloud), **только в стране**. Ядро: RDS Multi-AZ + логическая реплика в Cloud SQL (ЮАР) через Google DMS + ежедневный `pg_dump` (WAL-архив из RDS недоступен) |
| **Сроки хранения** | Консервативно до ответа Q-06: финансовые записи — 7 лет, KYC — 5 лет, логи — 90 дней (подробно — DRM §5) |
| **Согласия (C-07)** | Сервис согласий с первого дня; купленную базу 410 тыс. номеров **не загружаем**; подписка — через USSD-код в рекламе |

## Обоснование

Вариант 3 выполняет худшее правдоподобное прочтение NDPA за **+$990/мес** при одной платформе. Вариант 1 опирается на ошибку «шифрование снимает локализацию». Вариант 2 удваивает стек и не успевает к 15.10. Вариант 4 срывает дату: консультация юристов не может быть причиной не запускаться (C-06).

## Последствия

- (+) Ни одной записи и ни одного запроса с ПДн нигерийцев за рубежом (NFR-16); задержка в Лагосе < 10 мс. Шаблон ячейки тиражируется на 12–15 стран (A7).
- (−) Две точки входа, два набора воркеров, NAT-инстансы и self-managed PostgreSQL — нагрузка на 1 SRE. Компенсация — CloudNativePG, runbook, FMEA 14.
- (−) У Local Zone нет SLA, площадка одна: RTO ячейки — 4 ч ([failover-plan.md](failover-plan.md)). Межстрановая аналитика — только агрегаты; в WhatsApp-сообщениях нет ПДн покупателя (передача Meta за рубеж).

## Обратимость и триггеры пересмотра

**Триггеры:** заключение юристов (Q-06, до 19.09), ответ инвестора о провайдере (Q-01), запуск новой страны, изменения у регуляторов (NDPC, ODPC, Information Regulator).

| Если юристы ответят… | Что меняем | Срок |
|---|---|---|
| **Мягче:** псевдонимизированные заказы можно вне Нигерии | Таблицы заказов NG → ядро (скрипт миграции); PII-хранилище остаётся в Лагосе | 1–2 нед. |
| **Как допущено** | Ничего | — |
| **Жёстче:** нужен нигерийский оператор ЦОД | Ячейка → MTN Cloud: тот же Helm-чарт и Terraform, данные из уже лежащих там бэкапов | 2–3 нед. |
| **Жёстче для Кении** | Ячейка KE по тому же шаблону у кенийского оператора | 3–4 нед. |
| **Ключи тоже в стране** | KMS af-south-1 → HSM у MTN Cloud для OpenBao | 1 нед. |

**Код не переписывается ни в одном из случаев.** Обратимость держится на механизмах: таблица «страна → endpoint ячейки», API `tokenize` / `detokenize`, запрет межъячеечных JOIN, свои ключи в каждой ячейке, модуль Terraform `cell` с параметром `country`, бэкапы уже на альтернативной площадке.

## Assumptions

- AS-07, AS-30, AS-31 ([data-residency-map.md](data-residency-map.md)).
- **AS-34.** Ячейка NG в Г1 помещается в 2 × m5.xlarge (узлы EKS, не burstable) + 2 × m5.xlarge (PostgreSQL); проверяется нагрузочным тестом.
- **AS-57.** Поддержку AWS WAF для ALB в Local Zone нужно проверить; запасной вариант — ModSecurity и rate limiting в ingress ячейки (Shield Standard доступен).
