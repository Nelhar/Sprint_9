# Transition Architecture: сейчас → MVP → 6 мес. → 12 мес.

**Дата (время кейса):** 2026-08-31. **Принцип:** каждое состояние — работающая система. Переход идёт через **Strangler Fig** (выделение модуля в сервис за тем же API), а не через переписывание. «Швы», по которым режем, заложены в MVP: схема БД на модуль, межмодульные вызовы через интерфейсы, outbox, адаптеры партнёров, ячейки стран ([ADR-001](../Task2/adr-001-architecture-style.md), [ADR-003](../Task4/adr-003-data-residency.md)).

## Что меняется на каждом шаге и почему без переписывания

### Сейчас → MVP

- **Цель:** запуск 15.10 в пределах $5k/мес.
- **Строим:** монолит с «швами»: модули с отдельными схемами, outbox, адаптеры, ячейка NG со своей точкой входа.
- **Временные компоненты:** SQS вместо Kafka; ручные возвраты в бэк-офисе; онбординг продавцов силами оператора; pilot light вместо warm standby. **Для каждого записан срок удаления** — см. последний раздел.
- **Откат:** запуск по стране. Если Кения не готова (Daraja go-live), 15.10 запускается Нигерия, Кения — через 2 недели. Маркетинг предупреждён.

### MVP → 6 месяцев

- **Боль, которую закрываем:** уведомления — главный источник пиков (рассылки, стримы) и внешних отказов (FMEA 05, 06). В монолите они делят ресурсы с оформлением заказа.
- **Паттерн:** Strangler Fig. Модуль `notifications` уже общается с остальными только через outbox и очередь. Выделение = отдельный деплой + своя БД (журнал доставки). **Код модуля переносится, а не переписывается.** API для остальных модулей — та же очередь.
- **Переключение:** канарейка: 5% событий → новый сервис, 95% → модуль в монолите. Сверка доставки по DLR. Затем 100%.
- **Откат:** флаг маршрутизации возвращает события в модуль монолита (≤ 1 мин). Данные не теряются: источник правды — outbox. Строки outbox хранятся **7 дней** после публикации, поэтому повторная публикация возможна «начиная с `outbox_id` X» в пределах этого срока; дубли гасит дедупликация по `event_id`.
- **ЮАР:** новая ячейка по шаблону Terraform/Helm (`country=za`). POPIA: согласия уже есть в MVP. Платежи: Ozow и Paystack за тем же `PaymentProvider`, запуск — при доле EFT ≥ 80% (ADR-004).

### 6 месяцев → 12 месяцев

- **Боль:** 5 стран и B2B. Нужны новые ячейки и внешний API для партнёров.
- **Новые страны:** ячейки GH и UG по шаблону; Flutterwave и MTN MoMo — через тот же адаптер.
- **Partner API (B2B):** новый сервис с REST-контрактом поверх модулей каталога и заказов. Модули не трогаются.
- **Поиск:** внешний движок (OpenSearch или Typesense) за интерфейсом модуля `catalog.search`.
- **Kafka и Payments к 12-му месяцу не обязательны:** по плану TCO триггеры ADR-001 (> 500 событий/с, > 2 команды на модуле) срабатывают ближе к началу Г2. Если они сработают раньше, шаги ниже переносятся вперёд без изменения дизайна.

### 12 месяцев → Г2 (по триггерам)

- **Kafka:** outbox-relay начинает писать в Kafka вместо SQS. Потребители уже идемпотентны (дедупликация по `event_id`), поэтому переход — смена транспорта в адаптере. Период двойной записи — 2 недели, затем SQS отключается.
- **Сервис Payments:** схема `payments` уже отделена. Логическая репликация в новую БД → период двойного чтения со сверкой (SLI-PAY-3: 0 неразобранных расхождений 7 дней) → переключение записи. **Точка переключения:** нулевой лаг в обе стороны по LSN-меткам, объявленное окно «только чтение» для платежей ≤ 5 мин ночью, сверка SLI-PAY-3 за окно. Вебхуки PSP в окне получают **503, а не 200**: ответ 200 без записи в Inbox означает, что повтора не будет. Paystack повторяет (в live — каждые 3 мин первые 4 раза, затем раз в час 72 ч), Flutterwave — 3 раза через 30 мин при включённых повторах. Повтор callback у Daraja не гарантирован, поэтому заказы M-Pesa из окна закрывает STK Push Query джоба «зависших». Вебхуки PSP переводятся на домен сервиса. **Откат:** по тем же правилам — обратная репликация работает весь период перехода, переключение назад тоже при нулевом лаге.
- **Warm standby:** реплика Cloud SQL из pilot light становится постоянным тёплым резервом с поднятым GKE. SLO растёт до 99,95%, потому что цена минуты Г2 (≈ $788) это оправдывает ([Task3/nfr-registry.md](../Task3/nfr-registry.md)).

## Сводная миграционная матрица (временные компоненты и их удаление)

| Временный компонент | Вводится | Удаляется | Условие удаления |
|---|---|---|---|
| Онбординг продавцов оператором | MVP | 6 мес. | Онбординг через WhatsApp и веб |
| Модуль `notifications` в монолите | MVP | 6 мес. | Сервис на 100% трафика 2 недели |
| Ручные возвраты в бэк-офисе | MVP | 12 мес. | Автоматический сценарий возврата + антифрод v1 |
| Поиск на PostgreSQL | MVP | 12 мес. (или > 50 тыс. SKU) | OpenSearch или Typesense с паритетом выдачи |
| SQS как транспорт событий | MVP | Г2, по триггеру | Kafka в бою, 2 недели двойной записи без расхождений |
| Модуль `payments` в монолите | MVP | Г2, по триггеру | 7 дней двойного чтения без расхождений |
| Pilot light DR | MVP | Г2 | Warm standby прошёл DR-учение |

**Чего в переходе нет:** переписывания монолита, смены языка (Go остаётся), смены СУБД (PostgreSQL остаётся), смены облака. Целевое состояние CTO — много сервисов, шина событий, мультирегион — достигается **по триггерам**, а не к 15.10.

## Assumptions

- **AS-44.** Выделение сервиса = 3 чел-мес на модуль (оценка в [Task2/tco-model.xlsx](../Task2/tco-model.xlsx), лист «Стоимость ошибки»). Входит в рост команды до 11 FTE к 12-му месяцу (среднее Г2) и 17 FTE в Г3 (TCO A).
