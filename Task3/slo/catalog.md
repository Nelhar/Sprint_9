# SLO-контракт: Каталог (поиск, листинг, карточка товара)

**Владелец сервиса:** модуль `catalog` (команда ядра). **Потребители:** покупатели в приложении, диплинки из рекламы (A2). **Критический путь пользователя:** «услышал рекламу → открыл карточку → положил в корзину».

## SLI — что и как измеряем

| SLI | Тип (OpenSLO) | «Хорошее» событие | Все события | Где измеряется |
|---|---|---|---|---|
| **SLI-CAT-1 Доступность чтения** | ratioMetric | Ответ edge 2xx/304 на `GET /v1/products/*`, `/v1/categories/*` (в т.ч. отданный из кеша при ошибке origin) | Все такие запросы, кроме 4xx клиента | Логи CloudFront → метрика `cdn_requests_total{status}` |
| **SLI-CAT-2 Задержка API** | ratioMetric | Ответ origin быстрее 300 мс | Все запросы к origin каталога | `http_server_duration_seconds_bucket{route=~"/v1/products.*"}` |
| **SLI-CAT-3 Время до первого товара (RUM)** | ratioMetric | Первая карточка отрисована < 2 с от открытия приложения или диплинка | Все холодные и тёплые старты | Firebase Performance, трейс `first_product` |
| **SLI-CAT-4 Свежесть** | ratioMetric | Ответ не из stale-кеша **или** из stale-кеша с возрастом данных < 1 ч | Все ответы edge | Заголовки `X-Cache`, `Age` → `cdn_stale_age_seconds` |

## SLO — целевые значения

| SLI | Цель | Окно | Бюджет ошибок |
|---|---|---|---|
| SLI-CAT-1 | **99,95%** | 28 дней скользящее | 20 мин / 28 дней (≈ 0,05% запросов) |
| SLI-CAT-2 | **99%** запросов < 300 мс | 28 дней | 1% медленных запросов |
| SLI-CAT-3 | **75%** < 2 с, **99%** < 4 с | 7 дней | 25% / 1% сессий |
| SLI-CAT-4 | **99%**; отдача stale дольше 1 ч = деградация (SEV2) | 1 день | 1% |

Доступность выше, чем у оформления заказа (99,9%), и стоит дёшево: CDN отдаёт устаревший кеш при отказе origin (`stale-if-error`, [ADR-002](../adr-002-caching-strategy.md)). Но **«отдано из кеша» ≠ «каталог исправен»**: при «зелёном» SLI-CAT-1 цены и остатки могут устареть на сутки. Поэтому свежесть измеряется отдельно (SLI-CAT-4). Цена и остаток перед оплатой всё равно пересчитываются из БД.

```yaml
apiVersion: openslo/v1
kind: SLO
metadata:
  name: catalog-read-availability
  displayName: Каталог — доступность чтения
spec:
  service: catalog
  indicator:
    metadata: { name: catalog-edge-success }
    spec:
      ratioMetric:
        counter: true
        good:  { metricSource: { type: Prometheus, spec: { query: 'sum(rate(cdn_requests_total{svc="catalog",status=~"2..|304"}[5m]))' } } }
        total: { metricSource: { type: Prometheus, spec: { query: 'sum(rate(cdn_requests_total{svc="catalog",status!~"4.."}[5m]))' } } }
  timeWindow: [ { duration: 28d, isRolling: true } ]
  budgetingMethod: Occurrences
  objectives: [ { displayName: Доступность, target: 0.9995 } ]
```

## SLA — что гарантируется бизнесу и что происходит при нарушении

| Кому | Обещание (ниже SLO, чтобы был буфер) | При нарушении |
|---|---|---|
| CEO и маркетинг (внутренний SLA) | Карточка по диплинку открывается в 99,9% случаев за месяц, **особенно в часы рекламы и стримов** | Пост-мортем без поиска виноватых за 48 ч; **feature freeze** модуля до восстановления бюджета |
| Инвестор (дашборд) | Статус каталога виден на дашборде в реальном времени | — |

## Политика бюджета ошибок

- Сгорело **> 50%** бюджета — релизы каталога только с канарейкой 1% и ручным подтверждением.
- Бюджет исчерпан — freeze фич, команда занимается надёжностью: кеш, индексы, лимиты.
- Алерты по скорости сгорания: **paging**, если 2% бюджета сгорает за 1 ч (14,4×) или 5% за 6 ч (6×); **тикет**, если 10% за 3 дня (Google SRE Workbook, гл. 5).

## Assumptions

- **AS-55.** Окно 28 дней скользящее; для «время до первого товара» — 7 дней, чтобы быстрее видеть регрессии мобильного релиза.
- **AS-56.** Каталог — не ПДн, поэтому кеш CDN по всем странам не нарушает резидентность (ADR-002, ADR-003).
